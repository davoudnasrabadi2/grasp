    The scoring model, in the open

    Every credit the engine can give, with its weight. Weights are deliberately interpretable — this table ships with the product so teams can audit what "understanding" means.

    Scores decay with a 150-day half-life. "Current understanding" = score ≥ 55. When an agent rewrites a fraction f of a module, everyone's score on it is multiplied by (1 − 0.8·f) — the version they knew is gone.

    What is deliberately not counted

    Lines of code, commit counts, commit streaks, review counts as volume. Anything that can be farmed without comprehension is excluded — activity metrics measure effort, not understanding, and incentivize the wrong behavior.

    Privacy model

    Individual scores are visible only to the individual. Everything in the Manager view is aggregate: coverage counts per module, trends, alerts. There is no per-person report, no leaderboard, no export of individual levels. In the real product this is enforced server-side; in this demo it's enforced by the UI — same principle.

    Honesty box

    Understanding cannot be measured directly. Every signal is a proxy with failure modes; Grasp is a risk indicator, not a mind reader. The weekly report is designed to start conversations, not end them.
